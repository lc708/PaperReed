## 统一原则

冷白、石墨文字、系统无衬线字体、少量钴蓝。钴蓝只标记主要动作和交互焦点。默认页面只呈现完成当前任务所需的控件；账号异常与授权范围出现在相应页面，正常同步不占据收件箱。

这轮增加的是信息完整性与状态设计。首页仍没有常驻功能侧栏、AI 面板、头像墙或大量标签。

## 七个页面

| 页面 | 主要设计 | 可以实际体验的交互 |
| --- | --- | --- |

## 列表的信息规则

- **第一视线：寄信人。** 固定列宽；名字在一行内截断，完整内容在打开邮件后展示。多人往来显示轻量数量，不为每个人绘制头像。
- **第二视线：主题。** 未读主题和发件人共同加重。选中底色表示当前焦点，与未读状态分开。
- **第三视线：摘要。** 一行次级文字用于判断内容；不把正文塞进大卡片。当前版本保留摘要，以补足上一版需要逐封打开才能判断内容的问题。
- **最后一列：时间。** 使用固定列、等宽数字。时间和附件提示各占自己的行，时间不因悬停变成其他内容。
- **账号来源。** 统一收件箱与搜索结果只显示可自定义的颜色 / 形状标记，不逐行重复账号文字。悬停显示名称和地址，行的可访问名称仍包含账号；单账号列表省略标记。设置 → 账号管理可调整名称、颜色、方形 / 圆形 / 菱形。
- **置顶。** 分组表达，不在每一行重复徽章。置顶不等于未读，也不改变服务端文件夹。
- **附件。** 只有含附件的邮件才显示图标与数量。窄窗口也保留提示，不为没有附件的行放占位图标。
- **长文本。** 列宽不随长主题扩大；省略号不影响整行点击和打开全文。会话标题允许自然换行。
- **订阅。** 一条可展开行显示来源和数量；展开后使用同一套邮件行，不生成第二种卡片系统。

## 尺寸与排版

| 元素 | 参数 |
| --- | --- |
| 页面标题 | 24–27px / 640，字距 -0.8px |
| 会话标题 | 22–25px / 620，行高 1.45 |
| 列表发件人、主题 | 完整桌面 13px，紧凑桌面 12px；未读 610 |
| 列表摘要 | 11px；仅一行 |
| 账号、时间、往来数量 | 9–10px；不承担唯一的主要状态提示 |
| 正文 | 14px / 24px，普通邮件段落间 12px |
| 写信正文 | 14px / 24px；主题与会话同为 25px / 36px |
| 标准邮件行 | 64px；窄窗口改为两行结构，至少 84px |
| 列宽 | 寄信人 140–170px；主题弹性；时间 56–65px |
| 页面水平留白 | 紧凑桌面 40px，完整桌面 58px，窄窗口 23px |
| 控件圆角 | 普通控件 5px；弹层 8–10px；仅浮层有明确阴影 |

不通过整体缩放适应小窗口。窄屏将账号与姓名放在同一行，主题与摘要放在下一行；设置项适度换行，长页面正常滚动。

## 状态与行为

| 触发 | 结果 |
| --- | --- |
| 打开未读邮件 | 标记为已读；返回时“仅未读”会按更新后的状态过滤 |
| 仅未读没有结果 | 解释状态并提供“显示全部”，保留收件箱上下文 |
| 搜索无结果 | 保留关键词与筛选，提供重置入口 |
| 从搜索进入会话再返回 | 保留查询、邮箱范围和附件条件 |
| 归档 / 设置稍后 | 更新原型列表；短暂提示允许撤销 |
| 从稍后移回收件箱 | 清除提醒，保留原邮件，可撤销 |
| 写信或回复后离开页面 | 示例草稿留在当前原型会话中，可从草稿列表继续 |
| 收件人、主题、正文不完整 | 在发送演示前指出缺少的字段并聚焦 |
| 邮箱授权失效 | 说明缓存仍可阅读，提供重新连接流程入口 |
| 关闭 Agent 访问 | 禁用配置与权限控件；保留已选设置 |
| 配置 Agent | 先显示所选邮箱和操作范围；原型只模拟连接状态 |

快捷键：J / K 在列表中移动选择，在会话中切换邮件；Enter 打开，Escape 返回；E 归档，P 置顶，H 稍后，R 回复，C 写信，⌘K 命令。输入框、文本区域和中文组词阶段优先处理文本。模态窗口提供 Escape 与焦点循环。

## 实现和验证边界

- 主入口为 `direction.html`；`pages/` 内提供七个可独立打开的页面。
- 页面共用一个原型源文件；运行 `python3 design/build-previews.py` 更新独立页面，不分别维护七套视觉规则。
- `preview-checks.js` 只用于临时 HTML 检查，不进入交付原型。
- 已渲染检查七个桌面页面、窄窗口列表与写信页，并运行 17 项跨页面检查：页面 / ID / 横向尺寸、账号、未读、搜索过滤与返回、归档撤销、稍后排序与撤销、草稿、抄送与附件、设置、Agent、快捷键与模态焦点。
- 示例日期固定为 2026-11-14，提醒示例时区为纽约；正式产品使用系统时区和实际邮件时间。
- 所有邮箱、邮件与连接状态都是示例。附件选择只保留文件名称和大小，不上传文件；未接入真实收发、授权、Agent 配置或持久化存储。刷新原型会恢复初始数据。
- 真实邮件 HTML 隔离、富文本编辑器、同步任务状态、协议差异与系统窗口继续由既定架构承担，不在这次界面原型中重写。


## 第六版：统一阅读、编辑与 Agent 入口

- 列表以 18px 主行、4px 间隔、16px 摘要行组成；发件人、主题和时间顶端对齐。此前发件人带账号第二行、日期有时居中的布局已移除。
- 会话与新邮件采用同一 660px 内容区域、同一标题位置与字号、同一正文行高。阅读态是“主题 → 信封信息 → 内容 → 附件 → 回复”；编辑态是“可编辑主题 → 可编辑信封 → 编辑内容 → 附件 → 发送”。回复在原会话中原位展开，不另起第三种布局。
- 目前是共享排版规则的 HTML 原型；正式实现应复用同一个邮件内容组件，以阅读 / 编辑模式区分，保留现有隔离的 HTML 邮件渲染和富文本编辑器。
- 收件箱标题区、会话工具栏、写信与回复动作区提供同一个 Agent 入口。未安装时引导安装 CLI，安装后显示任务交接。CLI 安装和 Agent 配置是两个独立状态。
- 在账号管理里修改颜色与形状后，列表同步更新；不把整行、正文或选中状态染成账号色。
- 新增三项检查：账号颜色 / 形状自定义；CLI 引导 → Agent 配置 → 返回原草稿交接；未授权邮箱不能发起交接。总计 17 项通过。

详细交互与暂缓决定见 `AGENT-HANDOFF.md`。安装、配置和交接均为显式标注的演示，不执行本机安装或启动外部 Agent。
