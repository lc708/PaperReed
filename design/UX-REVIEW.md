# Mail UI/UX 评审与修正

状态：本报告记录评审建议和原型检查，不代表设计已获用户批准。当前设计仍未通过。

原则：让用户看懂当前位置、操作对象、可去的位置和操作结果，不依靠解释性文案补救结构缺陷。

范围覆盖收件箱、会话、写信、搜索、稍后、设置与 Agent。证据来自第六版源码 `direction-v6.html`、已有原型渲染，以及本轮改后原型的渲染与交互检查。下方图证是**根据原型源码绘制的结构示意，不是实机截图**。没有进行真实邮箱同步、外部 Agent 或真实用户测试；评审判断不代表用户研究结论。

## 1. 邮箱目的地隐藏在账号菜单中 · 高优先级

![修改前后导航结构](review-evidence/01.svg)

**现状事实：** 第六版 `act('scope')` 将账号范围、草稿、归档和设置放在同一菜单；没有已发送、垃圾邮件与废纸篓入口。

**影响判断：** 用户需要先猜中“所有邮箱”不仅是账号切换器。即使能找到，也不容易知道自己在哪个位置。

**修改：** 独立导航分成邮箱、整理、标签、偏好。宽窗口常驻，窄窗口用“邮箱与标签”展开；账号菜单只改变账号范围，不切换文件夹。展开导航提供键盘焦点与 Escape 返回。

**验收：** 不打开账号菜单，分别进入草稿、已发送、垃圾邮件与废纸篓。改变账号后保留当前文件夹。

## 2. 邮箱位置、状态和分类混在同一排 · 高优先级

![修改前后整理结构](review-evidence/02.svg)

**现状事实：** 第六版 `renderInbox()` 的三个主要入口是全部、置顶、稍后；没有自定义标签和分类规则编辑。

**影响判断：** 继续在同一排添加标签、通知、账号或文件夹会让入口不断膨胀；用户也容易误以为置顶和稍后就是全部整理方式。

**修改：** 文件夹决定“邮件在哪里”；收件箱分类决定“现在看哪类来信”；自定义标签表达“这封信属于哪些项目”。置顶与稍后是独立整理视图。默认分类为往来、通知、订阅，其他业务分类可通过自定义标签与规则扩展。

标签和规则提供新建、编辑、颜色、启用、匹配预览与应用范围。已有邮件默认不改动；勾选后可应用并撤销本次历史邮件变更。规则与标签当前仅在本机原型中模拟，不宣称已与服务商标签同步。

**验收：** 创建标签、批量添加、进入标签视图；新建“主题包含校样”的规则，预览 3 封匹配邮件，再选择是否处理已有邮件。

## 3. 高亮邮件与操作范围不一致 · 高优先级

![修改前后操作范围](review-evidence/03.svg)

**现状事实：** 第六版有单行键盘焦点，但没有复选选择；列表的 Agent 上下文来自整个列表。

**影响判断：** 用户可能把焦点高亮理解为已选中，进而误判 Agent 或批量整理会作用于哪封邮件。

**修改：** 焦点和复选框分开。桌面勾选框在悬停 / 聚焦时出现，窄窗口保持可见。选中后显示数量和批量操作；Agent 明确使用“选中邮件”。未勾选时才使用当前列表。配置 Agent 后返回原页面时保留所选范围。

**验收：** 勾选两封邮件，检查 Agent 上下文数量为 2；批量归档后撤销，原邮件回到各自位置；改变分类或目的地时清空跨范围选择。

## 4. 特殊位置缺少恢复路径，搜索范围未明确 · 中高优先级

![修改前后恢复与搜索结构](review-evidence/04.svg)

**现状事实：** 第六版 `restore()` 的撤销固定还原为稍后；`searchItems()` 只排除草稿。当新增垃圾邮件和废纸篓后，直接复用这些函数会产生错误的撤销位置与搜索范围。

**修改：** 新增已发送、垃圾邮件、废纸篓示例页面。垃圾邮件提供“不是垃圾邮件”，废纸篓提供“移回收件箱”；撤销记录实际原位置。搜索默认排除垃圾邮件与废纸篓，只有主动勾选才包含。原型不提供永久删除。

**验收：** 从两个位置分别恢复再撤销；确认回到原位置。搜索推广邮件默认无结果，勾选包含垃圾邮件后找到该邮件。

## 验证与后续边界

上述改后流程已执行；完整原型共 25 项交互检查。宽窗口导航、窄窗口导航及规则编辑弹层已渲染检查。

后续仍需在真实客户端验证：服务商标签 / 文件夹映射、同步失败和离线状态、大量邮件性能、规则冲突与后台执行、批量操作的逐项失败、垃圾邮件 HTML 安全渲染、VoiceOver，以及真实 CLI 的安装与唤起。不能以这个界面原型替代这些验证。
