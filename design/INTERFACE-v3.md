# 来信 · 界面方向 03

> 历史探索快照，未获最终批准。设计、架构和技术选型均未定稿；下文保留当时讨论措辞，当前状态以根目录 README.md 为准。

**选定方向：书信式编辑设计。** 先让人愿意读信，再让人快速处理邮件。此版替代第二版的视觉方案；技术架构与功能范围仍沿用 `ARCHITECTURE.md`。

## 设计判断

用户认为前两版嘈杂、功能堆砌、样式和图标普通。本轮不继续混合不同客户端的特征，选择一个一致方向：安静的书信阅读器。气质来自排版、比例和阅读节奏。每个常驻元素都必须证明它值得占用阅读注意力。

用户在工作之间收信，也会停下来读完一封长信。主界面只保留信件列表和当前信件；联系人、主题、正文是主角。多邮箱、归档、置顶、稍后、草稿、搜索与自动化仍属于产品能力，通过合适的入口呈现。

领域意象：来信、信封、落款、往来、纸面、订阅、归档。

色彩来源：暖白信纸、米灰纸背、石墨文字、褪淡的墨迹、橄榄绿书签。全界面采用统一暖灰关系，橄榄绿只辅助选中与操作。

识别特征：宋体主题与系统正文的组合、书信式落款、两栏之间明显不同的阅读节奏，以及一道细线标识的当前来信。

## 具体约束

- 默认两栏，没有第三列导航。完整桌面列表 268–290px，紧凑视图 218px；信件正文限制行宽，余下空间用于阅读留白。
- 邮箱与文件夹由“所有邮箱”入口切换。正常同步不显示状态条，异常时才显示相关反馈。
- 列表只显示寄信人和主题；未读使用字重。日期在悬停或键盘聚焦时出现。移除摘要、数字徽章、头像和逐行图标。
- 选中项使用 2px 橄榄绿细线和很浅的纸色变化；不使用高饱和选中块、阴影卡片或多色标签。
- 导航标题与信件主题使用 Songti SC / STSong，27–32px、常规字重。系统无相应字体时回退 serif。正文使用系统无衬线字体，桌面 14–15px、紧凑视图 13px，约 2.05 倍行高。宋体只影响客户端标题，不改写原 HTML 邮件的字体。
- 信件头部只常显寄信人和日期，点击寄信人显示完整地址与收件账号。上一封往来收在正文后，按需展开。
- 附件为一条轻量文件链接；回复沿阅读顺序放在信件末尾，原位展开。没有常驻富文本工具条或 AI 面板。
- 常驻“写信”“搜索”“归档”；其他整理操作放在一个文字菜单中。避免为了图标而增加图标。
- 订阅通过文字折叠行进入，不展示聚合卡片和来源标识墙。
- J / K 切换，E 归档，P 置顶，H 稍后，R 回复，C 写信，⌘K 搜索和命令。快捷键不占常驻底栏，输入与中文组词时让位给文本。
- 菜单使用清晰的文字和快捷键。归档与稍后提供短暂撤销反馈。窗口缩窄后在列表 / 阅读之间切换，保留返回入口。
- 外部 agent 接入与未来内置 AI 不改变默认阅读界面；相关设置和上下文动作按需出现。

## 保持简洁的边界

此轮只确定一个浅色方向，不并列设计多个皮肤。正式实现需继续验证深色、真实长邮件、收件人很长、多附件、同步失败与辅助功能；不能依靠缩小文字或隐藏必要异常来维持安静。

生产端仍使用原生 macOS 窗口按钮。原型绘制的窗口控件只表达比例，不作为产品实现。没有新引入 UI 框架、同步进程、数据库或云服务。
